# 审查 Agent 协议

审查 Agent 不是"另一个 LLM 上下文"这么简单：它是 K 阶段唯一的门。它跑在独立上下文里，
只看三样东西——**提案、证据原文、当前正式结构快照**，不看提案是怎么想出来的。

机械实现在 `scripts/summarize/review_agent.py`；本文说清每条检查的判据与边界。

## 一、它审什么

一次复盘产出两样东西，它都要审：

1. **沉淀本身**：这条候选是不是真的新、真的有据、真的会影响后续判断。
2. **刚产出的工作物**：论文卡、缺口卡、红队结论、教学答案有没有超出证据的断言、
   有没有漏掉必要对照、有没有和已生效的条款冲突（A2/A3 检查的就是这个）。

## 二、五项检查

| 检查 | 判据 | 实现方式 | 不过时 |
|---|---|---|---|
| A1 证据可回溯 | 引文必须在原文逐字命中（去空白后 `in`） | 确定性字符串比对，不调模型 | 直接驳回；无全文时转 `needs_source` |
| A2 结论不过度 | 出现"普适/所有/必然/最优/universal/always…"且来源 <3 时，必须加限定语 | 词表 + 来源计数 | 自动改写为"在该体系与所测算例下，……"后通过 |
| A3 一致性 | 同轴同类条款余弦 >0.6 且否定极性相反 → 冲突 | 向量比较 + 否定词检测 | 不覆盖，转争议单（`dispute`），并驳回原提案 |
| A4 必要性 | 与待审提案余弦 >0.9 | 向量比较 | 合并去重，驳回较晚的一条 |
| A5 风险分级 | 判断题归人，常规项归 Agent | 规则表 | 见下 |

A1 是整套机制里最硬的一道：它不依赖模型判断，改写的引文、拼接的句子、编造的页码都过不去。
论文没有全文时不要"猜着过"，而是转 `needs_source` 留在队列里，等 PDF 或全文索引补齐。

## 三、去向

| 去向 | 适用 | 批准者 | 可见性 |
|---|---|---|---|
| 静默入库 | 证据记录、补证、统计更新、明确重复合并 | Agent | 立即，抽样质检 |
| Agent 审后入库 | 新增演化边、技术族补充、描述性条款、单例观察升级 | Agent | 立即，工作台可撤销 |
| 升级人审 | 新轴晋升、拆分、合并、红线条款、平行范式、与用户钉住冲突、A2 降级后仍存疑 | 你 | 工作台 |
| 驳回 | A1 失败、A4 重复 | Agent | 未采纳日志 |
| 待补来源 | A1 无全文 | 挂起 | 队列 |

"审核后入库"依然成立，只是审核主体从"全由人"变成"Agent 审常规、人审判断"。
默认目标：升级率 ≤20%。

## 四、留痕与抽查

每条提案记录 `proposal_id`、五项检查结果、理由、引文定位、去向与时间（`review_log`）。
抽查方式：

```bash
python scripts/summarize_cli.py --ws <工作区> queue list        # 看自动入库清单
python scripts/summarize_cli.py --ws <工作区> eval              # Q8：A1 通过率、升级率、驳回率
```

- **A1 通过率长期 <98%**：抽取环节在编造或改写引文，要收紧 `evidence` 的粒度要求。
- **升级率长期 >20%**：A5 分级太保守，或者健康检查产出的判断题太多（例如把"降级"也归人审）。
- **驳回率高且被抽查推翻**：A3/A4 判据太激进，调阈值而不是关掉检查。

## 五、边界

1. 审查 Agent 不读提案人的推理过程，避免被说服。
2. 它不调用检索，不"帮提案补证据"；缺证据就退回，补证据是提案方的事。
3. 它不修改证据层，只改结构与提案状态。
4. 它不能绕过人审把 `candidate` 转 `stable`——晋升永远是人审。
5. 用户的钉住（`axes.pinned=1`）与手改优先级高于它的任何判定。
