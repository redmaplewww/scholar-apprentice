# 六阶段协议索引

> I 阶段（仪器落成）有独立详版：[`stage-I-instrument-commissioning.md`](stage-I-instrument-commissioning.md)。
> 本文件给 S / T / E / R / K 五个阶段的可执行摘要，并指明各阶段复用哪些已有资产，避免重写。
> 阶段不是流水线：E 的缺口常用 I 验证，R 暴露的仪器问题回 I，K 的教训回写 I 的检查表。

---

## S · 自学（Learn the field）

**目的**：把领域学到可验收，并把"学到什么程度"变成可查询的资产，供后续教学与探索引用。

**入口**：用户给出领域 + 目标产出（毕业论文方向 / 投稿目标 / 要解决的问题）。

**步骤**

1. 定标：领域边界、目标产出、验收线由谁定（一句话写进 `00-总进度.md`）。
2. 侦察：建 `研究档案/领域课程表.md`（六类模块：基础概念 / 理论与方法 / 工具与实践 / 历史与流派 / 经典与争议 / 前沿与开放问题）；同时建 `知识总账.md`（对照权威普查工件：综述目录、学科分类法、顶会 track、资格考试大纲…）。
3. 筑基：按模块走「学 → 织 → 测 → 联」，概念卡入卡库，单篇文献按三遍法做文献卡。
4. 校准：用已知答案题型盲测（细节问答 / 结论预测 / 综述对拍 / 审稿对拍 / 争议复述），通过率按「题型 × 难度」写进 `能力画像.md`。
5. 审核：独立审核代理对拍 + 领域讲解考核（讲不清学派分歧 = 未达标）。

**产物**：课程表、知识总账、概念卡库、文献卡、能力画像、缺口登记簿初版。

**门**：已知答案类 ≥80%（或与用户约定线）；能力画像里"未测试 = 未知"必须显式标注。

**失败模式**：只读综述不建卡（学完即忘）；能力画像只写通过项；把"我读过"当成"我会了"。

**复用**：`~/.agents/skills/apprentice`（双轨四阶段、12 铁律、三件知识资产）、`lrv-loop`（学→合卷复述→比对验证，验证基准 E→M→L 演进）、`da_toolbox.py`（总账/缺口/画像账本 + 答前门控）。

## T · 研讨（Teach and discuss）

**目的**：把已验证的知识转成用户的能力，并在研讨中暴露 AI 的知识边界。

**入口**：S 阶段已知答案类 ≥80%，或用户明确只想就某个子话题讨论。

**步骤**

1. 建学习者模型：概念 × Bloom 六级掌握度矩阵 + 研究者画像（方向、已有工作、可用资源、目标、偏好）。
2. 按意图选模式：导读 / 精读陪读 / 考核（反用 lrv：用户合卷复述，AI 对源逐条比对）/ 苏格拉底研讨 / 反转教学 / 想法会诊 / 组会模拟。
3. **提示阶梯**：追问 → 线索 → 部分答案 → 完整答案，每升一级须用户主动请求。
4. 收敛信号：用户能独立复述、能反驳、能提出未解问题。写进 `用户/研讨记录.md`。

**产物**：学习者模型、研讨记录、更新后的能力画像（学习维度）。

**门**：用户合卷复述零关键失配 + 覆盖率 ≥80%（与 lrv 同一标准）。

**护栏**：不代写研究问题与核心洞见；教学内容落在 AI 能力画像的失败区/未知区时显式告知；引用一律回查 ID。

**失败模式**：AI 抢答（认知外包）；只说"这部分我不确定"但不标来源；把研讨记录当成论文素材直接引用。

## E · 探索（Find the gap）

**目的**：在领域里找出**可做、值得做、还没被做**的方向，交用户裁决。

**入口**：S 完成；或用户带来一个方向要做查重与深化。

**步骤**

1. 态势图：子方向热度、想法发展链、方法×问题矩阵、矛盾与局限图。
2. 虫群检索：九个创新算子（局限聚合 / 矛盾边界 / 矩阵空格 / ABC 两跳 / 跨域类比 / 链条外推 / 前提挑战 / 趋势预测 / 用户锚点）作为检索路线；低产出的算子由零收益机制自动让出预算。
3. 想法成形：每条缺口 → 具体想法（问题、机理假设、可证伪预测、验证方案、所需资源）。
4. 红队：六维质疑（已被做过交给查重 / 前提 / 可行性 / 重要性 / 评测可信度 / 增量）。
5. 透明排序后交用户；**用户确认后**才做三级查重（关键词 → 嵌入+引用邻居 → 按 facet 比对最近 5–10 篇，给撞车五级）。
6. 深化：按查重结果把想法拆成可验证的研究问题（R 阶段入口）。

**产物**：缺口卡、想法账本（含已排除与理由）、查重报告、选题卡。

**门**：查重完成且撞车等级明确；用户书面确认方向。

**失败模式**：先查重后发散（把探索做成检索）；只报"新颖"不报最近邻；把"没检索到"当成"没人做过"。

**复用**：`swarm-search-kernel`（领域图搜索、信息素、提案复核）、`evkg`（主张图、对抗攻击）、AutoResearch（文献连接器、创新候选契约）。

## I · 仪器落成（Commission the instrument）

见 [`stage-I-instrument-commissioning.md`](stage-I-instrument-commissioning.md)。一句话：**在拿工具的数字说事之前，先证明它在我要用的范围内可信；证明不了就收缩可信范围，而不是假装可信。**

---

## R · 取证（Test the hypothesis）

**目的**：用已落成的仪器跑研究性算例，对假设给出判决。

**入口**：仪器卡存在且当前体系在覆盖范围内（`phase_gate.py check` 放行）。

**步骤**

1. 预注册：把假设、判据、成功/失败阈值、算例清单写进 `结果/<假设>-预注册.md`。**先写后跑。**
2. 执行：算例编号规则 `<instrument>-<体系>-<条件>-<序号>`；每次运行记录仪器版本、势/模型 sha256、可调设置、耗时。
3. 判读：用领域包定义的事件规则；判读结果必须能回到原始帧/原始数据。
4. 判决：支持 / 否定 / 不确定（含"仪器覆盖不足"这一合法结论）。
5. 归因：若否定，区分是假设错、输入错（领域输入）、还是仪器覆盖不足。

**产物**：预注册文件、结果档案（一案一档）、假设判决书、更新后的仪器卡"已知缺陷"。

**门**：每条结论都挂仪器卡 ID 与验收状态；不在覆盖范围内的数值一律标〔探索性·未验收〕且不进结论段。

**失败模式**：先跑后写判据（后见容差）；只报成功的算例；把"仪器覆盖不足"写成"现象不存在"。

---

## K · 沉淀（Codify）

**目的**：把这次的做法变成下次的默认，把这次的教训变成红线。

**入口**：任一轮 R 完成，或同类任务第二次出现。

**步骤**

1. 抽 SOP：把这次跑通的步骤写成可复制流程（输入 → 动作 → 产物 → 判据）。
2. 抽红线：每条踩过的坑写一条可检查的红线（"看到 X 就必须做 Y"）。
3. 分流归属：按核心/领域包判据归档（换个领域就不成立 → 领域包）。
4. 回归测试：为新红线补一条可机械检查的测试（脚本或清单项）。
5. 版本化：SOP 升版号，红线带日期；旧结论若被新红线推翻，标记作废并重出。

**产物**：SOP 新版本、红线清单增量、回归测试、领域包版本号。

**门**：新红线有对应检查手段；否则只是口号，不算沉淀。

**失败模式**：把"这次怎么做的"写成叙事而非流程；红线不可检查；教训只留在对话里。

## 阶段间硬约束（跨阶段也要守）

| 约束 | 说明 |
|---|---|
| 数字出生证 | 任何自产数值：仪器 ID / 版本 / 验收状态 / 覆盖范围 / 是否在范围内，五问缺一即降级 |
| 三级来源标注 | 〔已验证·有出处〕/〔模型记忆·待核对〕/〔未知·缺口〕 |
| 制审分离 | 生成与审核用不同上下文；复核者的证据不得与提案来源重叠 |
| 诚实定性 | 复现 ≠ 增量；定性一致 ≠ 定量一致；"没检索到" ≠ "不存在" |
| 覆盖范围收缩 | 允许部分落成，但必须精确声明能用/不能用，不许删表 |
